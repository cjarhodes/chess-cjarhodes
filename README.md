# chess-cjarhodes

A static, single-page chess training app served at
[chess.cjarhodes.com](https://chess.cjarhodes.com). No build step, no
backend required — `index.html` and `app.js` run entirely in the browser,
with vendored copies of every third-party library.

## Modes

**Library** — Guided study of 28 openings across 35 total lines (main
lines plus attached variations, e.g. the Italian Game links to the Evans
Gambit, Fried Liver Attack, and Blackburne Shilling as sub-lines). Each
line has move-by-move explanations and key ideas. A quiz mode tests
recall of the moves (moves you have not reached yet stay hidden), tracked with a lightweight SM-2 spaced-repetition
scheduler (`localStorage` key `chess_sr_v1`) that surfaces lines as
new/learning/due/mastered.

**Puzzles** — A tactics trainer built on 2,750 puzzles from the
[Lichess puzzle database](https://database.lichess.org/#puzzles) (CC0),
balanced across ratings 400–2800 and tactical motifs. `puzzle-data.js` is
generated by `scripts/build-puzzle-data.py` and loads only when Puzzles opens.

- *Rated puzzles* use a Glicko-1 puzzle rating. The full history stays in this
  browser (`chess_puzzles_v1`, scoped to the account like other training
  data); a compact copy (last 120 attempts, rating, bests, daily results) rides
  in the synced training profile, so it reaches other signed-in browsers and
  training backups and merges back in on load. The first wrong
  move, a hint or the solution counts as a miss; the puzzle can still be
  finished. The motif and puzzle rating stay hidden until it is solved.
  Theme filters, first-try strengths and weaknesses by motif (with sample
  sizes), and an unrated replay of any recent puzzle.
- After each puzzle the full solution is shown in notation. **Review missed
  puzzles** replays, unrated, every puzzle whose latest attempt was a miss
  until you solve it first time.
- *Daily puzzle* is the same for everyone on a calendar day and unrated.
- *Puzzle Rush* (3 min, 5 min or Survival): difficulty climbs with each
  solve, three mistakes end the run, and the run can be reviewed afterwards.
  Rush never changes the puzzle rating.
- *Vision* is a 30-second coordinate drill on a board without coordinates,
  from either side.
- *Endgame practice* plays classic won endgames (queen, rook and two-rook
  mates, king-and-pawn key squares, the Lucena bridge) against full-strength
  Stockfish until you reach the goal within the move limit. Losing material,
  stalemate or running out of moves ends the run; hints draw the engine's
  move but a hinted run does not set a best (`endgames.js`, tested by
  `scripts/validate-endgames.js`).

When Progress names a focus with a tactical twin (missed mates, loose
pieces, forks, pins, king safety, endgames and so on), it also offers
**Solve … puzzles** on that theme (`PuzzleCore.INSIGHT_GROUPS`).

Shortcuts in Puzzles: `H` hint, `S` solution, `R` retry, `F` flip, `N` next.
Press `?` anywhere (or the **?** button in the header) for the shortcuts of
the current view; in Coach, `←`/`→` step through the game, `Home` goes to the
start and `End` back to the live position (`shortcuts.js`).
Logic lives in `puzzles-core.js` (tested in Node by
`scripts/validate-puzzles.js`, which also replays every shipped puzzle);
`puzzles.js` owns the view; `scripts/verify-puzzle-journeys.js` drives it in
the browser.

**Explore** doubles as an analysis board: Stockfish's top three lines
(depth 14) for the position on the board, an evaluation bar and a best-move
arrow, with a click on any line playing its first move. **Load a FEN or PGN**
sets up any position or game (Undo steps back through a PGN). It works
without a Lichess token and can be switched off (`ui:explore-engine`);
quizzes never show it (`explore-analysis.js`).

**Explore** — Browse the Lichess Opening Explorer's master/lichess
game databases from any position. Requires the user's own Lichess
Personal Access Token, which is kept in `sessionStorage` only (never
`localStorage`, and any legacy `localStorage` copy is actively cleared
on load) so it does not persist across browser sessions.

**Coach** — Play a full game against the vendored Stockfish engine
(WASM), with every move classified against engine evaluation into
tiers (best, excellent, good, inaccuracy, mistake, blunder). After the
game, a post-game review summarizes accuracy, phases, and key moments.
Missed moves feed a practice/drill loop — spaced review of your own
mistakes, independent of the Library's opening quizzes. Coach works
fully local-only; optionally signing in with Supabase makes games,
mistakes, practice attempts, and trends durable across devices and
browsers. Leaving `coach-config.js` blank keeps Coach local-only.

The Coach board shows its feedback on the board as well as in the panel:
a move-quality badge on the square your reviewed move landed on (it stays
there after the reply while your piece does), a green arrow for the engine's
choice when stepping back to a move that wasn't among its best, the next move
of a **Show why** line, and an evaluation bar beside the board (dimmed when it
is from before the latest move). Drills hide all of it. **Appearance &
sounds → Arrows, move badges and evaluation bar** turns it off
(`ui:board-feedback`). `board-overlay.js` draws on any chessboard.js board;
`coach-overlay.js` decides what Coach shows.

Engine-first moves can also earn **Great (!)**, the only good move with a
clear gap to the second-best line, or **Brilliant (!!)**, a sound sacrifice
that leaves a minor piece or more en prise while staying best. These are
display flags on top of the tiers, so accuracy and insights are unchanged
(`move-flair.js`, tested by `scripts/validate-move-flair.js`).

**Opponents** (Game setup): besides the adaptive Coach, six personalities
from Pip (400, early queen raids) to Ines (2400, universal). Each is a level
on the calibrated strength slider plus an opening repertoire from the
Library: while the game follows one of its lines, it plays the book move;
off book, the calibrated engine plays as usual. Choosing one is the same as
setting the slider (adapting turns off); moving the slider makes it a custom
level; choosing Coach turns adapting back on (`opponents.js`, tested by
`scripts/validate-opponents.js`).

Move reviews start with a short explanation. **Show why** steps through the
recommended line on the main board without changing the live game; **Back to
game** restores the actual position. Engine details remain expandable.
Practice recommends one lesson or a bounded session of distinct positions from
your games. Session labels match the actual length; repeated weakness tags do not
repeat the same position and answer. Lessons state their objective, explain
misses, highlight staged hints, and show position-level progress. Practice borrows
the board and returns to the same unfinished game when closed.
Drills evaluate sound alternatives, provide progressive hints, and can ask for
a follow-up after an opponent reply. Unverified engine results are not counted
as mistakes.

Library visits preserve the current drill or selected review position. Both
workspaces fit their boards and tools to the desktop viewport. Post-game reviews
keep the takeaway and next actions visible while supporting details scroll.

**Opening → game** carries a selected Library position and idea into free,
unrated Coach play, including variations and completed quizzes. Finished mating
lines back up to a playable student decision. After a few reviewed moves, the
review separates engine move quality from the player's self-reported use of the
idea. Up to six recent opening reviews remain in Progress and training backups.
An unfinished Coach game is protected, including when a drill temporarily
borrows the opening game or the browser reloads. See the
[opening transfer audit](docs/opening-transfer-loop.md).

**Learning transfer** adds an optional different-position check after rehearsal.
The first graded decision stays separate from hints, retries, and later rehearsal.
Progress keeps the result and cue, offers rehearsal or play, and shows up to six
actual follow-up reviews without treating absent flags as proof of learning.
Saved games and opening sessions return intact. See the
[learning transfer audit](docs/learning-transfer-loop.md).

**Progress** leads with one next focus, its evidence, a cue, and a direct action to
practice or play. It resumes an unfinished session before suggesting a new one.
Activity, unassisted attempts, assisted completions, and observed mistake rates
are shown separately. Repeated instances of one position count as one due drill.

The practice comparison uses the nearest 30 reviewed moves before an unassisted
completion and the first 30 after it. Further rehearsals keep an eligible
checkpoint while its baseline remains in the retained history. Thirty moves is
a practical descriptive floor, not a statistical significance test or proof of
learning. Monthly trends use flags per reviewed move rather than raw counts.
History keeps up to 300 reviews, and imported games use their review dates.
See [the useful progress audit](docs/useful-progress-loop.md) for workflows,
measurements, and remaining evidence limits.

**Activity** (Progress) shows twelve weeks of training days, combining
reviewed moves, drill attempts, puzzles and finished games, with how many
of the last 14 days had any and the current streak. It counts activity, not
improvement (`activity.js`, tested across time zones and daylight-saving
changes by `scripts/validate-activity.js`).

**Game archive** (Progress) keeps the latest 40 finished Coach games, and
separately the latest 40 games imported by username, in this browser with their move-by-move review (`coach:archive:v1`, scoped to the
account). Opening one shows a viewer with its own board: step with the arrow
keys or by clicking a move or the evaluation graph; each reviewed move shows
its badge, and mistakes show the engine's choice as an arrow. On an inaccuracy, mistake or blunder,
**Retry this move** lets you play the position again (on the board or typed):
the engine's choice is accepted, and so is any of its top three moves it rates
within half a pawn of it; **Show answer** draws the engine's move. Copy the PGN
or delete the game there. The archive is included in training
backups (Training data → Export), and importing merges games by id. The live
game is never touched (`game-archive.js`).

**Import by username** (Import games → From Chess.com or Lichess) lists your
20 most recent standard games from the public Chess.com or Lichess game list
(Chess.com: the last two months). Only the username is sent. **Review** grades
your moves with the same engine review as Coach, and saves the game in the
archive with its opponent, site and a link back to it. Like a pasted PGN, a
reviewed game counts in Insights, the practice queue and the personal
repertoire, but the live Coach game is left alone. A review can be stopped;
nothing is saved until it finishes (`game-import-core.js`, `game-import.js`).
The CSP allows `https://api.chess.com` and `https://lichess.org` for this, and
`validate-security.js` pins the full `connect-src` list.

PGN import reviews all selected-side moves in the valid games in a batch,
with progress and cancellation. A completed batch contributes to Insights
and repertoire evidence; the final game's review is shown in Coach. Cancelling
discards the staged batch rather than saving a partially analysed history.

Account continuity keeps each browser's session in its own account checkpoint.
In **Account**, choose **Continue saved session** to continue a separate copy;
the source browser is unchanged, and **Return to previous session** keeps the
board you displaced recoverable. Copies are unrated and do not add inherited
reviews to lifetime game totals. New moves still receive normal coaching.
Backups include live boards, interrupted practice, opening context, and training
history; importing offers the saved board separately. Offline move reviews and
takebacks retry when you reconnect or choose **Sync now**. **Sign out here**
affects this browser's session. See [the account continuity audit](docs/account-continuity-loop.md).

## Stack

- `index.html` + `styles.css` + `app.js` (runtime) + `openings.js` (opening content data)
  + `opening-transfer.js` (Library-to-game exercises and reviews)
  + `learning-transfer.js` (different-position checks and follow-up observations)
  + `account-continuity.js` (saved-session copies, offline review retries, safe backup imports)
  + `growth.js` (personal training layer: profile, repertoire, imported games,
  endgames, cross-device sync)
  + `puzzles-core.js` / `puzzles.js` / `puzzle-data.js` (Puzzles view) — no
  build tooling, no package manager, no framework
- Vendored libraries (see `vendor/` and `stockfish/`):
  - `chess.js` 0.10.3
  - `chessboard.js` 1.0.0
  - `jQuery` 3.6.0
  - `@supabase/supabase-js` 2.114.0
  - Stockfish (WASM build: `stockfish.js` + `stockfish.wasm`)
- Lichess Opening Explorer API for Explore mode
- Optional Supabase project for account-backed Coach sync
- Desktop-first by design: the board scales with the window height, the
  rails use the width a laptop or desktop offers, and screens narrower than
  1024px get a notice recommending a larger screen (with a continue option)
  instead of a mobile layout.
- Browser-only by design: there is no web app manifest and nothing registers
  a service worker. `service-worker.js` remains only as a kill switch that
  unregisters and clears caches for browsers that installed an earlier
  version; `scripts/validate-schema.js` enforces this.

## Local preview

Serve the folder over plain HTTP so workers and browser security rules
behave the same as in production:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

Then open `http://127.0.0.1:4173/`.

## Validation

Run before committing any change to `app.js` or `index.html`:

```sh
node --check app.js
for f in scripts/validate-*.js; do node "$f" || exit 1; done
```

The validators run pure logic in Node (practice scheduling, difficulty,
review teaching, transfer checks, recovery, progress) and check shipped
files: the openings data (every line replayed as legal chess), design tokens
and colour contrast, migrations and CI (`validate-schema.js`), and security.
None of them pattern-match the app's source for function names.

For browser coverage (Library, Coach, the practice loop, the journeys, and
`scripts/verify-behaviour-units.js`, which drives engine failure, threat
scanning, sign-in URLs, auth storage, sync, retry, storage and clipboard
failures, accessibility and themes in the running app), run:

```sh
scripts/verify-browser.sh
```

To re-measure opponent strength after changing the difficulty model, run
`node scripts/calibrate-difficulty.js`. It samples every slider level over ~60
positions with the vendored engine and prints average centipawn loss, severe
blunder rates, and mate-in-one concessions (several minutes). Samples use a
repeatable seed; override `SAMPLES`, `SEED`, or `LEVELS` as needed. To compare
an older selector on the same suite, set `APP_FILE=/path/to/old-app.js`.

Difficulty numbers are approximate, not measured Chess.com, Lichess, or FIDE
ratings. Move-quality statistics alone cannot establish a human Elo rating.
The opponent searches at full native skill, then samples bounded alternatives
more often at lower settings. It favors smaller mistakes, retains sound moves,
converts known mates, and avoids engine-detected forced losses when a non-mating
line exists. This is a weakened engine, not a model trained on human moves.

The browser suite checks the coaching UI at 1280×800, 1440×900, and 1920×1080,
including keyboard focus, board/control visibility, session start and resume,
review, practice recovery, and completion. Screenshots are written beneath
`output/playwright/`. See [the UI improvement audit](docs/coaching-ui-loop.md).

The browser suite also finishes mating endings and six-turn opening sessions at
400, 1200, and 2400, checking legal replies, reviews, results, and reloads. See
[the opponent-quality audit](docs/opponent-quality-loop.md) for measurements and limits.

This drives a real browser via `playwright-cli` (resolved from `$PWCLI`,
a local Codex Playwright skill, an installed `playwright-cli`, or
`npx @playwright/cli` as a last resort) against a local `http.server`
instance.

### Supabase schema changes

Coach's optional account sync is backed by Supabase. Schema changes go
into a new file under `supabase/migrations/`, applied with a local
Docker-backed reset/test or a linked `supabase db push`. See
[SUPABASE_SETUP.md](SUPABASE_SETUP.md) for the full setup, local
reset/test flow, and security notes (RLS, disabling open signups, key
handling). `supabase-schema.sql` is a readable canonical reference kept
in sync with the versioned migrations, but the migrations remain the
actual deployment mechanism.

## Deploy

Hosted as the Vercel project `chess-cjarhodes` with custom domain
`chess.cjarhodes.com`. Pushing to `main` triggers an automatic build and
deploy (usually live within ~30 seconds). Security headers (CSP,
`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
`Permissions-Policy`) and the `www` -> apex redirect live in
`vercel.json`.

## Workflow

1. Edit `index.html`, `app.js`, or the relevant vendored/config file.
2. Run `node --check app.js` and every `scripts/validate-*.js`
   validator.
3. Run `scripts/verify-browser.sh` for the repeatable smoke coverage.
4. For schema changes, add a Supabase migration and run a local reset
   or linked `supabase db push`.
5. Commit and push to `main`; Vercel auto-deploys to
   chess.cjarhodes.com.
6. Confirm the deployment and smoke-test the custom domain.
